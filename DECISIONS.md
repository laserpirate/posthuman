# DECISIONS

One line per judgment call. Newest at the bottom.

- Preflight answers (2026-10-22): repo `laserpirate/posthuman` public; 30 s default duration; crossfade 2 s; all 58 in pool, 7 favorites starred and as the starting playlist; no credits or title cards in full screen.
- Read "2 30 x" as 30 seconds.
- `Z:\_F26_Fall-2026\9_post-human\posthuman\` already holds the post-human26 gated site (remote post-human26), so the app lives in `posthuman-vj\`.
- Credits line shows only in windowed mode; it is never drawn in full screen or in Clean output (projector), per preflight answer 5. The Credits toggle controls the windowed line.
- Site served from the repo root on Pages (`main` `/`), with `.nojekyll`; build tools live in `tools/` and are public but harmless.
- Font: Chakra Petch 500/600 (UI) and Martian Mono 400 (code overlay, readouts), bundled woff2 from @fontsource, OFL.
- Accents: lime #c4f53c (on) and red #ff4f63 (warn/blackout/quarantine). Squared controls everywhere.
- Header reading for all 58 sketches is a fixed table in tools/build-data.mjs (headers are irregular); untitled sketches are titled "Untitled".
- "CNDSD" (Malitzin Cortés's handle in the header) is used as the author for malitzin_*; "e_e" for eerie_ear_*; "Naoto Hieda" for the @naoto_hieda sketches.
- Sketches that read `a.fft` get a silent audio stub (`a.fft = [0,0,0,0]`), so they run without mic input; sketch code stays verbatim.
- Before each eval: hush, reset speed/bpm/fps, two ticks to flush feedback buffers, time = 0.
- Pause stops the autoplay timer only; the current sketch keeps animating.
- A playlist cannot contain the same sketch twice; Add on a sketch already in the list is a no-op with a log line. Makes reorder/current tracking unambiguous.
- Quarantined sketches can still be played by hand from the gallery or playlist; autoplay and random pull never pick them.
- Black/white check: a 160×90 readback once a second; black = brightest channel < 10, white = darkest > 245, for more than 3 s.
- On WebGL context loss: log, save, reload the page after 2 s (state restores from localStorage).
- Code overlay state is not persisted and is turned off when entering full screen; C turns it on there.
- Blackout state is persisted, so a reload during a blackout stays black.
- Auto quality drop is per session (not saved); the chosen level is saved.
- Share links carry only the playlist (name, ids, durations), not `?i=`, so the receiving laptop keeps its own instance.
- robots.txt and ai.txt are copied for parity, but GitHub project Pages serve them under /posthuman/, where crawlers do not look; the noindex/noai meta tag is what counts.
- Sketch functions that throw are caught inside hydra-synth, which only prints console.warn('ERROR', e) each frame; the app intercepts that warning while a deck ticks and treats it as a failure (skip + log). Same rule in the preflight harness.
- Preflight frame cost is measured with a 1 px readPixels after each tick (forces the GPU to finish); "slow" means p95 over 41.7 ms (under 24 fps) at 1280×720.
- Preflight quarantines code that needs a camera, screen, video, image or network input (offline shows); only flor_1 (initCam) hits this.
- Stills are 320×180 JPEG, grabbed 4.5 s into each sketch on the RTX 3080; preflight rewrites them only with --thumbs.
- Frame cap allows 8 ms of slack so 30 fps holds on 60 Hz displays with jitter (was 4 ms, which gave about 28 fps headed).
- Enter commits a number field and blurs it so shortcut keys work again; selects blur after a change.
- Random mode: a bag of every playable item except the one on screen; it refills when empty. Each cycle plays every item once.
- Random "from pool" uses every non-quarantined, non-banned sketch, not only the playlist.
- Stretch, output window: the controller owns the clock and the playlist and sends what to show over BroadcastChannel `phvj:<instance>`; the output renders on its own two decks, never writes storage, and reports failures back so the controller skips.
- Stretch, output window: while an output window is connected the controller preview rests (no ticking) to save GPU on older laptops; a Live tab checkbox keeps it running.
- Stretch, output window: in the output window only F and double-click work (full screen); everything else is driven from the controller.
- Stretch, audio: RMS of the filtered band, attack at once, release by the Smooth slider; zoom and brightness on a wrapper around both decks so crossfades are unaffected. Off by default, saved per instance.
- Stretch, audio: Mids is a bandpass centered at 1.73 kHz with Q 0.87 (covers 1 to 3 kHz).
- Stretch, tempo: Tap averages up to the last 8 taps (a gap over 2 s restarts); with "every N bars" each sketch runs N × 4 beats. Four or more taps also restart the current sketch's clock so the switch lands on a bar line.
- Stretch, hold: Hold freezes the countdown on the current sketch (G); Play/Pause stays separate.
- Stretch, ban: per instance and saved; banned sketches never autoplay, are skipped at once if on screen, and can still be played by hand.
- First soak (pre-fix code) found a 404 for favicon.ico (counted as a console error) and slow heap growth; added an empty data: favicon.
- Heap snapshots traced the growth to hydra-synth's hush(): Source.clear() makes a new 1×1 texture per source without freeing the old one (4 WebGL textures leaked per switch). The app frees them before hush; vendored hydra-synth stays unmodified.
- Remaining per-switch heap noise is V8 code for each `new Function` eval and Chrome's layout-shift buffer (capped at 150 entries); both bounded.
- The soak pass rule allows under 2 MB growth between the first and last third of samples, after forced GC.
- Handoff-3 #1 root cause: in full screen #bar becomes position: fixed (and in clean/out/menu-off it is display: none), so it leaves the grid flow and #main is auto-placed into grid row 1, which those modes size to 0 px. The stage had zero height, so the screen showed only the black body. Fix: pin #bar to row 1 and #main to row 2. The output window had the same flaw.
- Full screen: if the Fullscreen API is missing or refused, the app enters the same layout as a full-window mode (Esc or F leaves it). Double-click on the stage also toggles full screen.
- Full screen menu: synthetic mousemove events with no movement (Chrome sends them when the cursor hides or layout shifts) no longer reset the 3 s auto-hide. Found only in the headed run.
- E2E now checks real screen pixels (Playwright screenshot of the stage, decoded with pngjs) for full screen, transitions, quality change, 20 toggles, clean output and the output window.
- Interrupted soak #2: the visible soak window at ?i=soak was used by hand (random on, High 60 fps, held). Later soaks run headless (same RTX 3080 via ANGLE D3D11) so they cannot be touched.
- Stars: one star set per instance, shown on gallery cards, playlist rows and the menu bar (S). "Playlist from starred" makes or replaces a playlist named Starred.
- Audio v2: five bands analysed at once (Full, Low = lowpass 150 Hz, Mid = 1 to 3 kHz, High = highpass 6 kHz, Custom lo..hi); each has sensitivity, smoothing, threshold and a meter. Zoom and flash each pick their own band, so two bands run at once. The v0.1 Kick/Bass presets became Custom buttons (40-120, 60-250 Hz). Levels exposed as window.A.
- Live edit lives in a Code tab (controller only). Run evals on the deck on screen with no hush and no time reset; any Run while autoplay is playing turns Hold on so the edit is not switched away.
- Live edit errors: a syntax/eval error, or a runtime error inside a sketch function (hydra's ERROR warning), shows inline in red and the last good code is evaluated again. An edited deck is never auto-skipped and is not black/white checked (the edit is the user's choice).
- Knobs: a literal is a knob only when it is a whole argument of a hydra function whose input type is float (from hydra-synth's own glslTransforms definitions, which also give the names). Literals inside arrays, strings, comments, arrow function bodies or non-hydra calls (Math.max) are skipped. Callees after a dot count only when chained on a call result.
- Knobs attach on first use: one eval swaps each knob literal for ()=>PHK[slot][i] (same look, no time reset); later slider moves only change PHK. Each attach gets a new slot and slots older than four back are dropped, so a fading deck keeps reading its own values.
- Knob range: 0 to 4× the value (negative values mirror), with a span of at least 1; editable min/max fields. Audio link per knob: value + depth × level × (max − min).
- The code text shows knob values as plain numbers when there is no unsaved typing in the box; Bake runs that text, so the values become plain literals and the knobs detach.
- Variants: saved per instance as "<title> (edit)", credited "edited from <title> by <author>", with the original's still; listed in the gallery and credits; ids start with v_. Share links to variants do not carry the code, so another laptop drops them.
- The output window follows Run and knob values (BroadcastChannel 'run'/'knobs'); a newly opened output gets the running edit too.
- Phone layout: #app and #panel grid columns are minmax(0, 1fr) so long playlist rows and the menu bar no longer push the page wider than the screen. The phone test now checks every element against 390 px (mobile emulation zooms out, so innerWidth was not a fixed reference).
- Show input (handoff-3 revision): any input whose label contains Scarlett or Focusrite is picked automatically, ahead of the instance's remembered choice; otherwise the remembered device, else the default. Labels are hidden before the first permission grant, so the app opens an input, re-reads the list, and switches once if a Scarlett shows up.
- Unplug: the track's ended event, or the device leaving the list on devicechange, stops audio (levels to 0, effects off) but keeps Audio reactive armed. The Live tab shows "Input lost" in red. Reconnects on devicechange, with a 3 s poll as a backup because devicechange does not fire on every driver, when the same device or any Scarlett/Focusrite is listed again.
- SHOWNIGHT.md is new in this repo. The SHOWNIGHT.md in ..\posthuman3026 belongs to the other build and was not touched.

## v0.3.0 · Kodama mode (handoff-5)

- Preflight answers: kodama files published **encrypted on Pages** (option b; this overrides the handoff-2 "no password or encryption" rule for the kodama pack only, as Marko chose); pk26 airfield, pk27 under-city, pk28 drowned towers, pk29 cloud city as plain working titles; 90 s default; palette on entering Kodama mode is a setting (Original by default, with Grayscale, Duotone, B/W, Mono, Red/green offered).
- Safety tag `posthuman-v0.2.2-pre-kodama` pushed before any change. Kodama mode sits behind its own mode switch; the Hydra e2e (27 tests) ran green after every step.
- Two packs: plain in `local/kodamas/` (gitignored; copied to laptops; `node serve.mjs` serves it) and encrypted in `kodamas/` (committed). The app tries the plain folder first, then the encrypted pack. AES-256-GCM, key from the password by PBKDF2-SHA256 (250,000 iterations); every file is its own IV + ciphertext; file names are numbers so even scene names stay private. The password lives in `local/kodama-pass.txt` (gitignored). The salt is kept across rebuilds so remembered keys keep working.
- "Remember on this laptop" stores the derived AES key (not the password) in localStorage, shared by every `?i=` instance on that browser. The controller hands the key to its output window over the BroadcastChannel (same browser, same origin).
- All scene files are read (and decrypted) into memory when the pack opens: about 1 MB, so a scene switch never waits on the network and loading stays synchronous like the hydra decks.
- Library files are never edited. `tools/kodama-import.mjs` copies them byte for byte; the app rewrites at load time: the cdnjs three.js tag points at `vendor/three.r128.min.js` (MIT, vendored), the `phylla-kodama-manifest.js` tag is inlined, and `kodama-rig.js` is injected ahead of everything. Scenes play in srcdoc iframes (same origin).
- Visuals only: the rig hides every non-canvas element with `visibility:hidden` (not cropping; buttons stay clickable) and turns off pointer input. Tested per scene by hiding the canvas and checking the stage is pure black.
- Clock: the rig replaces the scene's requestAnimationFrame, performance.now and Date.now. The app's one rAF loop steps the scene; each step is 1/60 s of scene time and the speed slider sets how many steps run per displayed frame (several above 1x, one every few frames below 1x; capped at 8). Only the last step of a frame renders. This scales both clock-based and per-frame animation, which the library mixes. Below 1x the scene updates less often rather than in smaller steps (smooth enough at 0.25x and up; steppy at 0.1x).
- Turntable: every library scene orbits with a global `camA` incremented per frame, gated by `turntable` (or `autoSpin` in kv01–kv08). The rig switches the scene's own spin off and adds rate × slider per step, so 0 stops, 2 doubles and Reverse turns back. Rates come from the scene source via the registry. A rotate-the-scene-root fallback exists for scenes without `camA`; none use it.
- `data/kodama-controls.json` is generated from the scene HTML by `tools/kodama-registry.mjs` (group label + data-attribute selector per button; `#tt` and the sound button are left out because the turntable slider and silence replace them). Hand entries go in its HAND table; none were needed. Clicks are proxied by selector; the pressed state is read back from the scene's `.on` classes four times a second. The registry is public (it holds button labels like "dawn", not scene content).
- Camera height/zoom slider: not built (not cheap across scenes that each clamp camY/camR differently). Drag-to-orbit is off.
- Kodama decks are their own pair of slots (no new hydra instances; still exactly 2). The incoming scene's fade (and even a cut) waits for its first rendered frame, so no black gap. The outgoing iframe is torn down after the fade: `renderer.dispose()`, `forceContextLoss()`, then the iframe is removed.
- Skip rules for kodamas: a throw (inside the scene's frame, or an error event in its document), no first frame within 15 s, black or white for 3 s, or WebGL context lost. The black/white probe reads only on frames the scene rendered, since some scenes do not preserve their drawing buffer.
- One mode plays at a time. Each mode keeps its own pool, playlists, stars, bans, cue, hold, position and failures (`phvj:<i>:k:*` keys for kodamas); switching saves the current position, stops its decks (hydra decks hushed, kodama iframes removed), fades through black (0.45 s each way) and restores the other mode where it was. Play/pause carries across the switch. The output window gets the same fade and follows on the next show message.
- Panel: the Gallery tab becomes "Kodamas" in Kodama mode (the library of the mode that is playing). A new Scene tab holds the mirrored controls, speed, turntable and the palette. Share link is hidden in Kodama mode (private scenes). Live edit says it works on Hydras.
- Drafts (pk26–pk29) are in the library marked "Draft, pending approval" and left out of the default Kodamas playlist.
- Palettes: one SVG filter on a wrapper around both deck types: contrast (linear transfer), luminance (color matrix), a map (discrete table for B/W, tables for mono/duotone/red-green), then mixed back with the original by intensity (arithmetic composite). Original at contrast 1 removes the filter entirely (zero cost). Red/green gradient map is a three-stop map, black to red to green, so it differs from the flat red/green duotone preset. Hydras and Kodamas each keep their own palette; a playlist row's Pal button snapshots the current palette onto that item.
- The contact sheet of the drafts is `local/kodamas/contact-sheet.jpg` (gitignored), linked from MORNING.md by path, not committed: the public repo should not carry images of the unreleased drafts.
- New scenes were built by four parallel agents from a shared brief (pk18/pk17 conventions, perf budget, mood-only use of the reference board, no creatures, no copied images). Each is self-contained (no manifest script), so their titles live in their own HUD, which the rig hides.

## v0.4.0 · approvals, palette fix, view controls, four mashups (handoff-6)

- No preflight questions (handoff-6 says run autonomously). Safety tag `posthuman-v0.3.1-pre-h6` pushed before any change.
- pk26 to pk29 approved: the draft flag is gone (`tools/kodama-import.mjs`, `local/kodamas/index.json`) and they are in the default Kodamas playlist. An instance that already had a Kodamas playlist gets them appended once (remembered in `phvj:<i>:k:approved`, so removing one by hand sticks). Working titles unchanged.
- Palette root cause: not a rendering failure. On Polaris in headed Google Chrome every palette changed the real screen pixels (OS screen copy, `tools/palette-screen.mjs`) on the controller and in the output window, windowed and in full screen, even at High. Marko's own Chrome storage showed what went wrong: he had changed the "Kodama start" dropdown (grayscale, then red/green, then B/W), which only applied on entering Kodama mode and did nothing live. Each re-entry into Kodama mode also reset the live palette to that start value, and his live palette sat at 0.68 intensity, which mutes every style.
- Palette fix, UI: Palette is now the first thing in the Scene tab, and Kodama mode has a palette dropdown in the menu bar. P cycles styles. "On start" is a clearly separate row that also applies at once when changed. The start palette applies only once, when the app opens; going to Hydras and back keeps the palette.
- Palette fix, item override: when the item on screen has its own palette (Pal), the Scene tab says so ("Editing the own palette of …", plus a "Use the mode palette" button), the controls edit that item palette, and the menu bar shows it. Before, the controls changed the mode palette, which the item palette then hid.
- Palette fix, rendering (robust path as asked): no filter on a wrapper any more. Kodamas: kodama-rig.js puts the SVG filter defs into the scene's own document (on `<html>`, outside the hidden overlays) and sets the canvas's CSS filter there. Hydras: the same filter goes straight on the two hydra canvases. The CSS-only and WebGL fallbacks were not built, because the SVG filter worked on every path tested on screen.
- Kodama scaling moved inside the iframe: the iframe covers the letterboxed stage and the rig reports the quality size as innerWidth/innerHeight, so the scene still draws at Low/Med/High and its canvas is stretched by CSS. The filter then runs after the upscale, so B/W stays exactly two values (it showed mid greys at edges when the filter ran before a scaled iframe).
- Camera: input is read by the app on the stage, controller and output window alike, and the pad. The rig sets the scene's own camA/camY/camR, at the scene's own drag rates and inside its own clamps, parsed from each scene's handlers into `data/kodama-controls.json` (`cam`: ka, ky, kr, y, r, pan). The scene's own pointer handlers stay off (iframe pointer-events none). This gives the same feel as re-enabling them, but one path also drives the pad and the output window, and double-click full screen and the menu auto-hide keep working. The drag hints stay hidden.
- Pan: shift-drag or right-drag. The rig offsets the camera and its look point (`target`) together at render time and undoes it after, so scenes that orbit the origin pan properly without code changes. The pan is limited to half the scene's nearest zoom (`cam.pan`), and the camera height stays inside the scene's camY limits. Hand entries: pk27 under-city pan 3 (interior); kv14 has no camY drag in the scene (its vertical drag moves target.y), so vertical orbit is off there and pan covers it.
- Turntable and steering: every steer holds the turntable for 2 s (rig.hold, scene real time), then it resumes from the new angle. A scene's own spin is cancelled during the hold too.
- Sync: each steer sends an absolute view {a, y, r, px, py, pz} over the BroadcastChannel (at most every 30 ms, always the last). The output window applies it and holds its turntable; a drag in the output window is sent back with from: 'out' and the controller applies it without echoing. A view for a scene the output has not started yet waits for its first frame.
- Reset view: back to the scene's own starting view (captured at its first step), pan zeroed.
- View override: a View button on Kodama playlist rows saves the current view of the scene on screen. It applies on the scene's first frame, then the turntable continues from there. Saved with the playlist like Pal.
- A scene file missing from local/kodamas/ is now left out of the pack instead of failing the whole pack.
- Mashups pk30 to pk33 built by four parallel agents from one brief: pk26 to pk29 as templates, the registry-parsable camera and button conventions, the perf budget, mood-only refs. Drafts, out of the default playlist.
- `kodamas_manifest.csv` in ..\All_Kodamas gained rows for pk26 to pk33. pk26 to pk29 had not been added in handoff-5.
- Addendum 7a (overnight rules) read mid-run: handoff-6 continued where it stood. "Palette transition" in 7a is read as handoff-6's palette fix; its setting is the Scene tab Palette row (and "On start").
- On-screen palette test: Marko's Claude desktop window was in front of the test browser, and Windows does not let a background process take the foreground. `tools/front.ps1` makes the test window topmost by a unique title while it is measured.
- Leak check before every push: `tools/leak-check.mjs` scans every tracked file for the password, each scene's title, seed and a line of its code, and JPEG data in kodamas/ (it catches a planted title).
- e2e-kodama: `KODAMA_PASS=none` runs the live test with no password (locked pack).
- Pushes that change only docs or test tools after a green gate are not re-gated; any change to app code, the rig or the pack is.
